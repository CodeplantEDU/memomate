## 1. 개요

### 1.1 문제
메모, 할 일, 일정이 여러 앱에 흩어져 있으면 무엇을 언제 해야 하는지 한눈에 보이지 않습니다. 그리고 적어둔 일을 제때 떠올리지 못해 놓치게 됩니다.

### 1.2 목표
"적어두면 → 정리되고 → 제때 알려준다." 이 흐름을 하나의 로컬 웹 앱에서 끝까지 해결합니다.

### 1.3 대상 사용자
- 강의, 업무, 개인 일정을 동시에 관리하는 개인 사용자
- 로그인이나 클라우드 없이 내 PC에서 가볍게 쓰고 싶은 사용자

### 1.4 제품 원칙
1. **설치와 로그인 없음:** `start.bat`을 더블클릭하면 바로 실행됩니다.
2. **데이터는 내 PC에만:** localStorage에 저장하고, JSON으로 백업합니다.
3. **3초 규칙:** 앱을 열면 오늘 할 일이 3초 안에 보여야 합니다.
4. **입력은 빠르게:** 할 일 하나를 알림까지 걸어 저장하는 데 10초를 넘기지 않습니다.

### 1.5 목표 지표 (자가 점검용)
| 지표 | 목표 |
|---|---|
| 할 일 입력부터 알림 설정까지 걸리는 시간 | 10초 이내 |
| 알림 정확도 (탭이 열려 있을 때) | 예정 시각 ±30초 |
| 놓친 알림 표시율 | 앱을 다시 열었을 때 100% |
| 첫 화면 표시 | 항목 1,000개 기준 1초 이내 |

## 2. 1단계: 기본 기능 (✅ 완료, 기준선)

현재 구현된 기능입니다. 2·3단계는 이 기능들을 깨뜨리지 않아야 합니다(회귀 금지).

| 영역 | 기능 |
|---|---|
| 메모 | 자동 저장, 검색, 태그·폴더, 고정, 색상, 휴지통, `- [ ]` 체크박스와 할 일 연동 |
| 할 일 | 마감일(날짜), 우선순위(상·중·하), 하위 할 일, 반복, 필터 |
| 캘린더 | 월간·주간 보기, 일정(종일·시간 지정), 한국 공휴일(2025~2027) |
| 공통 | 오늘 화면, 통합 검색, JSON 백업·복원, 다크 모드, 모바일 대응 |

**현재 데이터 모델 (요약)**
```js
memos:  { id, title, body, tags[], folder, pinned, color, date, aiExcluded, createdAt, updatedAt, deletedAt }
todos:  { id, title, done, due /*YYYY-MM-DD*/, priority, parentId, repeat, repeatDay, spawned, memoId, memoOrder, createdAt, updatedAt }
events: { id, title, start, end, allDay, note, createdAt, updatedAt }
settings: { theme, lastExport }
```
> ⚠️ `todos.due`에는 **날짜만** 있고 시각이 없습니다. 2단계 알림을 위해 시각 필드를 추가해야 합니다(§3.4).

## 3. 2단계: 알림

### 3.1 목표
할 일, 일정, 메모에 알림을 걸 수 있고, 제때 알림을 받으며, 놓친 알림도 빠짐없이 확인할 수 있게 합니다.

### 3.2 사용자 스토리
| ID | 사용자 스토리 | 우선순위 |
|---|---|---|
| N-1 | 할 일에 마감 시각을 정하고 "10분 전"에 알림을 받고 싶다 | P0 |
| N-2 | 일정이 시작되기 전에 미리 알림을 받고 싶다 | P0 |
| N-3 | 알림을 받으면 바로 완료하거나 10분 뒤로 미루고 싶다 | P0 |
| N-4 | 앱을 닫아둔 동안 놓친 알림을 다시 열었을 때 보고 싶다 | P0 |
| N-5 | 받은 알림을 알림함에서 다시 보고 싶다 | P1 |
| N-6 | 메모를 특정 날짜·시각에 다시 보고 싶다 | P1 |
| N-7 | 아침에 앱을 열면 오늘 할 일과 일정 요약을 보고 싶다 | P1 |
| N-8 | 밤이나 수업 중에는 알림이 울리지 않게 하고 싶다 | P2 |

### 3.3 기능 요구사항

#### 3.3.1 알림 설정
- **할 일:** 편집 폼에 `마감 시각`(선택)과 `알림` 드롭다운을 추가합니다.
  - 선택지: 없음 / 정각 / 5분 전 / 10분 전 / 30분 전 / 1시간 전 / 1일 전 / 직접 입력(날짜+시각)
  - 마감 시각이 없는데 상대 알림(예: "10분 전")을 고르면 설정의 `기본 알림 시각`(기본 09:00)을 기준으로 계산합니다.
- **일정:** 일정 폼에 `알림` 드롭다운을 추가합니다. 종일 일정은 "당일 기본 알림 시각"과 "전날 기본 알림 시각" 중에서 고릅니다.
- **메모:** 메모 상단 메뉴에 `다시 알림`을 추가합니다(날짜+시각 직접 입력).
- 항목 하나에 알림은 **최대 3개**까지 걸 수 있습니다.
- 반복 할 일은 다음 회차가 생성될 때 알림 설정(오프셋)을 그대로 이어받습니다.

#### 3.3.2 알림 발송
- 30초마다 검사기가 돌면서 `fireAt <= 지금`이고 `status = pending`인 알림을 발송합니다.
- **발송 방식**
  1. 브라우저 알림(Notification API): 권한이 허용된 경우 Windows 토스트를 띄웁니다.
  2. 앱 안 배너: 화면 오른쪽 위에 토스트를 띄우고, 사용자가 닫을 때까지 유지합니다.
  3. 알림음: 설정에서 켜고 끌 수 있으며 기본값은 켜짐입니다.
- 탭이 백그라운드일 때 브라우저가 타이머를 늦출 수 있으므로, `visibilitychange`로 탭이 다시 보일 때 즉시 한 번 더 검사합니다.
- 여러 탭이 열려 있으면 `storage` 이벤트와 잠금 키로 **한 탭에서만** 발송합니다(중복 알림 방지).

#### 3.3.3 알림 동작
알림 배너와 알림함 항목에서 다음 동작을 할 수 있습니다.
| 동작 | 결과 |
|---|---|
| 완료 | 할 일이면 완료 처리하고, 알림 상태를 `done`으로 바꿉니다 |
| 10분 뒤 | `fireAt = 지금 + 10분`, 상태를 `snoozed → pending`으로 되돌립니다 |
| 내일로 | 할 일 마감과 알림을 하루 미룹니다 |
| 열기 | 해당 항목의 편집 화면으로 이동합니다 |
| 닫기 | 상태를 `dismissed`로 바꿉니다 |

브라우저 토스트는 클릭하면 앱 탭에 포커스를 주고 해당 항목을 엽니다(토스트 자체의 버튼은 브라우저마다 지원이 달라서 사용하지 않습니다).

#### 3.3.4 놓친 알림
- 앱을 시작할 때 `fireAt < 지금`인데 아직 발송되지 않은 알림을 **놓친 알림**으로 분류합니다.
- 오늘 화면 맨 위에 "놓친 알림 N개" 카드를 표시하고, 몰아서 처리할 수 있게 합니다(모두 확인 / 개별 동작).
- 7일보다 오래된 놓친 알림은 자동으로 `dismissed` 처리하고, 알림함에만 남깁니다.

#### 3.3.5 알림함
- 상단 바에 벨 아이콘을 두고, 읽지 않은 알림 수를 배지로 표시합니다.
- 목록은 최근 30일 기록이며, 탭으로 `예정` / `받은 알림` / `놓친 알림`을 나눕니다.
- 예정 알림은 알림함에서 바로 수정하거나 삭제할 수 있습니다.

#### 3.3.6 아침 브리핑
- 그날 처음 앱을 열 때(또는 설정한 브리핑 시각에 탭이 열려 있으면) 요약 모달을 띄웁니다.
- 내용: 오늘 일정 수와 목록, 오늘 마감 할 일, 기한이 지난 할 일, 오늘 다시 볼 메모
- 설정에서 끌 수 있으며, 같은 날에는 한 번만 표시합니다(`settings.lastBriefing`).

#### 3.3.7 방해 금지 (P2)
- 설정에서 시간대를 지정합니다(예: 22:00~07:00, 요일 선택 가능).
- 방해 금지 중에는 토스트와 소리를 끄고 알림함에만 쌓습니다. 시간대가 끝나면 "방해 금지 중 받은 알림 N개" 배너를 띄웁니다.

#### 3.3.8 권한 처리
- 알림을 처음 설정할 때 Notification 권한을 요청합니다(앱을 열자마자 묻지 않습니다).
- 권한을 거부하면 앱 안 배너와 소리만으로 동작하고, 설정 화면에 "브라우저 알림이 꺼져 있음" 안내를 표시합니다.

### 3.4 데이터 모델 변경
```js
// 신규 저장 키: 'memomate.reminders'
reminder: {
  id,
  targetType: 'todo' | 'event' | 'memo',
  targetId,
  mode: 'relative' | 'absolute',   // 상대(오프셋) / 직접 지정
  offsetMin: number | null,        // relative일 때, 예: 10 = 10분 전
  fireAt: ISOString,               // 실제 발송 시각(계산값)
  status: 'pending' | 'fired' | 'snoozed' | 'done' | 'dismissed' | 'missed',
  firedAt: ISOString | null,
  read: boolean,
  createdAt, updatedAt
}

// todos 확장
todos.dueTime: 'HH:MM' | null

// settings 확장
settings: {
  ...,
  notify: { sound: true, defaultTime: '09:00', briefing: true, briefingTime: '08:00',
            dnd: { enabled: false, start: '22:00', end: '07:00', days: [0,1,2,3,4,5,6] } },
  lastBriefing: 'YYYY-MM-DD' | null
}
```
- 대상 항목의 마감이나 시작 시각이 바뀌면 `relative` 알림의 `fireAt`을 다시 계산합니다.
- 대상 항목이 삭제되면(휴지통 포함) 연결된 `pending` 알림을 `dismissed`로 바꿉니다. 휴지통에서 복원하면 미래 알림만 되살립니다.
- 기존 1단계 데이터는 그대로 읽혀야 하며, 새 필드는 `normalize`에서 기본값으로 채웁니다.
- JSON 백업과 복원에 `reminders`를 포함합니다.

### 3.5 화면 변경
| 위치 | 변경 |
|---|---|
| 상단 바 | 벨 아이콘과 배지 |
| 할 일 폼 | 마감 시각, 알림 선택 |
| 일정 폼 | 알림 선택 |
| 메모 메뉴 | 다시 알림 |
| 오늘 화면 | 놓친 알림 카드(맨 위), 알림이 걸린 항목에 🔔 표시 |
| 신규 | 알림함 화면, 아침 브리핑 모달, 알림 토스트 |
| 설정 | 알림 섹션(소리, 기본 시각, 브리핑, 방해 금지, 권한 상태, 테스트 알림 버튼) |

### 3.6 제약과 결정 사항
- **탭이 열려 있어야 정시 알림이 울립니다.** 로컬 HTML과 localStorage 구조에서는 탭이 닫힌 뒤 알림을 확실하게 보낼 수 없습니다. 이 한계는 "놓친 알림"으로 보완하고, 상주 알림은 4단계(데스크톱 앱)로 미룹니다.
- 서비스 워커와 PWA는 2단계에 넣지 않습니다(탭을 닫았을 때 알림이 보장되지 않고, 복잡도만 늘어납니다).
- `http://localhost`에서 실행해야 Notification API가 동작합니다. `start.bat` 방식은 그대로 유지합니다.

### 3.7 인수 기준
- [ ] 할 일에 "마감 14:00, 10분 전 알림"을 설정하면 13:50±30초에 토스트, 배너, 소리가 나온다.
- [ ] 알림 권한을 거부해도 앱 안 배너와 소리는 동작한다.
- [ ] "10분 뒤"를 누르면 10분 뒤에 다시 울린다.
- [ ] 마감 시각을 바꾸면 상대 알림 시각도 따라 바뀐다.
- [ ] 탭 2개를 열어도 알림은 한 번만 울린다.
- [ ] 알림 시각이 지난 뒤 앱을 열면 놓친 알림 카드에 표시된다.
- [ ] 반복 할 일의 다음 회차에 같은 오프셋 알림이 생성된다.
- [ ] 항목을 삭제하면 연결된 알림이 울리지 않는다.
- [ ] 아침 브리핑은 하루에 한 번만 뜬다.
- [ ] 1단계 데이터가 담긴 백업 JSON을 복원해도 오류 없이 동작한다.
- [ ] 방해 금지 시간에는 토스트와 소리가 나오지 않고 알림함에 쌓인다.

## 4. 3단계: 편의 기능

### 4.1 목표
입력과 정리를 더 빠르게 하고, 지난 한 주를 돌아볼 수 있게 합니다.

### 4.2 사용자 스토리
| ID | 사용자 스토리 | 우선순위 |
|---|---|---|
| Q-1 | "내일 3시 회의 30분 전 알림"처럼 한 줄로 입력하면 일정과 알림이 함께 만들어지길 원한다 | P0 |
| Q-2 | 어디서든 단축키로 빠른 입력창을 열고 싶다 | P0 |
| Q-3 | 캘린더에서 일정이나 할 일을 드래그해 날짜를 옮기고 싶다 | P1 |
| Q-4 | 이번 주에 무엇을 끝냈고 무엇을 미뤘는지 보고 싶다 | P1 |
| Q-5 | 자꾸 미뤄지는 할 일을 모아서 정리하고 싶다 | P1 |
| Q-6 | 할 일을 드래그해서 순서를 바꾸고 싶다 | P2 |

### 4.3 기능 요구사항

#### 4.3.1 자연어 빠른 입력
- 상단 바에 빠른 입력창을 두고, 단축키 `Ctrl+K` 또는 `/`로 엽니다.
- 입력하는 동안 아래에 **해석 미리보기**를 표시합니다. 예: `📅 일정 · 11/27(금) 15:00 · 🔔 30분 전`
- `Enter`로 저장하고, `Tab`으로 종류(할 일 / 일정 / 메모)를 바꿉니다.
- 규칙 기반 파서로 구현합니다(AI 없음). 지원하는 표현은 다음과 같습니다.

| 분류 | 예시 |
|---|---|
| 상대 날짜 | 오늘, 내일, 모레, 글피, 다음 주, N일 후 |
| 요일 | 월요일, 이번 주 금요일, 다음 주 화 |
| 절대 날짜 | 12/3, 12월 3일, 2026-12-03 |
| 시각 | 3시, 오후 3시, 15:00, 3시 반, 저녁 7시, 아침 9시 |
| 알림 | N분 전 알림, N시간 전, 하루 전 |
| 우선순위 | `!` 또는 `중요` → 상, `!!` → 상(강조) |
| 태그·폴더 | `#강의`, `@업무` |
| 반복 | 매일, 매주 월요일, 매달 1일 |
| 종류 추정 | 시각과 "회의·약속·수업" 같은 단어가 있으면 일정, 그 밖에는 할 일, `메모:`로 시작하면 메모 |

- 해석하지 못한 부분은 제목으로 남기고, 미리보기에서 사용자가 직접 고칠 수 있게 합니다.
- "3시"처럼 오전·오후가 모호하면 1~6시는 오후, 7~11시는 오전으로 추정하고 미리보기에 표시합니다.

#### 4.3.2 단축키
| 단축키 | 동작 |
|---|---|
| `Ctrl+K` / `/` | 빠른 입력 |
| `Ctrl+F` | 통합 검색 |
| `G` 다음 `T`/`M`/`D`/`C` | 오늘 / 메모 / 할 일 / 캘린더로 이동 |
| `N` | 현재 화면에서 새 항목 |
| `Esc` | 모달이나 입력창 닫기 |
| `?` | 단축키 도움말 |
- 입력 필드에 포커스가 있을 때는 한 글자 단축키를 무시합니다.

#### 4.3.3 캘린더 드래그 이동
- 월간 보기에서는 일정과 할 일을 다른 날짜 칸으로 드래그해 날짜를 바꿉니다.
- 주간 보기에서는 시간 지정 일정을 위아래로 드래그해 시각을 바꿉니다(15분 단위).
- 이동하면 연결된 상대 알림을 다시 계산하고, 화면 아래에 "실행 취소" 토스트를 5초 동안 띄웁니다.
- 모바일에서는 길게 누른 뒤 드래그합니다.

#### 4.3.4 주간 회고
- 새 화면 `회고`(또는 오늘 화면 아래쪽 섹션)를 만듭니다.
- 이번 주(월~일) 통계
  - 완료한 할 일 수, 요일별 막대 차트
  - 새로 만든 할 일 수와 완료 수의 비교
  - 기한이 지난 할 일 수
  - 가장 많이 쓴 태그 상위 5개
- 지난주와 비교(증감 화살표)하고, 이전 주로 넘겨볼 수 있습니다.
- 차트는 외부 라이브러리 없이 SVG로 직접 그립니다(단일 파일 유지).

#### 4.3.5 미룬 일 모아보기
- 마감일을 2번 이상 미뤘거나 기한이 3일 이상 지난 할 일을 "미룬 일"로 분류합니다.
- 일괄 동작: 오늘로 / 다음 주로 / 마감 없애기 / 삭제
- 데이터: `todos.postponeCount`(마감일을 뒤로 바꿀 때마다 +1)

#### 4.3.6 할 일 순서 변경 (P2)
- 할 일 목록에서 드래그해 순서를 바꿉니다. 정렬 방식을 "직접 정렬"로 골랐을 때만 동작합니다.
- 데이터: `todos.order`

### 4.4 데이터 모델 변경
```js
todos.postponeCount: number   // 기본값 0
todos.order: number | null    // 직접 정렬용
settings.todoSort: 'auto' | 'manual'
completedAt: ISOString | null // todos에 추가, 회고 통계용(1단계 데이터는 updatedAt으로 추정)
```

### 4.5 인수 기준
- [ ] "내일 오후 3시 팀 회의 30분 전 알림 #업무"를 입력하면 내일 15:00 일정, 14:30 알림, 태그 `업무`가 만들어진다.
- [ ] 해석 미리보기가 입력과 동시에(100ms 이내) 갱신된다.
- [ ] 위 §4.3.1 표의 표현마다 테스트 문장 2개 이상이 올바르게 해석된다.
- [ ] 입력 필드 안에서 `N`이나 `/`를 눌러도 단축키가 실행되지 않는다.
- [ ] 일정을 드래그로 옮기면 알림 시각도 함께 바뀌고, 실행 취소로 원래대로 돌아간다.
- [ ] 회고 화면의 완료 수가 실제 완료 기록과 일치한다.
- [ ] 미룬 일 일괄 처리 뒤 목록과 캘린더에 즉시 반영된다.

## 5. 비기능 요구사항 (2·3단계 공통)

| 분류 | 요구사항 |
|---|---|
| 구조 | 단일 `memomate.html` 유지, 외부 라이브러리와 CDN 없음 |
| 호환성 | 최신 Chrome, Edge (Windows 11 기준). 모바일 브라우저는 알림을 제외하고 동작 |

| 다크 모드 | 신규 화면과 컴포넌트 모두 라이트·다크 테마 지원 |

## 부록 A. 4단계 이후 (범위 밖)

아래 항목은 이 PRD의 범위가 아니며, 3단계가 끝난 뒤 별도 PRD로 다룹니다.

- **AI 보조:** Claude API로 메모 요약, 할 일 쪼개기, 하루 계획 추천, 자연어 입력 보완 (`memos.aiExcluded` 필드는 이미 있음)
- **상주 알림:** Tauri 또는 Electron 데스크톱 앱 전환, 트레이 상주, 탭이 닫혀도 울리는 알림
- **PWA 설치:** 서비스 워커, 오프라인 캐시
- **동기화:** 여러 기기 간 데이터 동기화, 외부 캘린더(Google, Outlook) 연동
- **공유:** 메모나 할 일 목록 공유
